# Design-system and build decision — candidate, 28 November 2026

This is an incremental candidate, not a completed flagship transformation or a release authorization. See `OPERATOR_HANDOFF_CANDIDATE.md` for the unchanged safety and deployment requirements.

## Evidence and decision

The previous exact Worker was 399,911 bytes raw and 122,428 bytes gzip (level 9); its 400,000-byte CI ceiling left 89 bytes. CSS was 75,619 source bytes, 75,416 served bytes. Client JS was 9,765 bytes. The Worker contains three-language server-rendered educational copy, CSS, JS and the logo. The 400 KB threshold was an internal engineering rule, **not** the platform limit. Cloudflare's [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) currently document 64 MiB uncompressed and a one-second startup limit; the latter is not measured by byte count. [Pages limits](https://developers.cloudflare.com/pages/platform/limits/) give a 25 MiB per-static-asset limit. Neither reference proves our account's actual performance, entitlement, asset routing or deployed safety.

Options considered:

* **Separate CSS/JS into Pages assets:** removes about 85 KB raw from the Worker and permits caching independent of it, but changes deployable package and ASSETS routing precisely where the six public HTML paths and current asset provenance remain unresolved. A mock is not evidence of actual Pages routing or isolation. Defer until the operator proves the complete asset manifest, exact bytes, preview bindings and rollback path.
* **Modularize educational source:** valuable for ownership and translation review, but concatenation means splitting files alone saves no delivered bytes. The guide-data JSON minification experiment increased its bytes (22,905 to 22,943). Do not promise runtime savings or change rendering boundaries without measurement.
* **Optimize the existing build:** earlier duplicate CSS pruning preserved screenshots; moving the root tokens into `tokens.css` and adding a shared `signature.css` compiles to the same single versioned endpoint. Before adding visual rules, this refactor produced a byte-identical Worker (SHA-256 `35bdc915c71a83170d8e33f179064f09f9314b67c7971bea41bd4c38cb7c749d`). The build remains string-injection-based and must still fail closed when its anchors change. Replacing it with an untested bundler is not justified by size alone.
* **Revise internal guardrails:** choose a bounded, explicitly provisional raw Worker ceiling of 450,000 bytes (~12.5% over the former rule), with an additional 140,000-byte gzip ceiling (~14.4% over the prior candidate) to detect less compressible growth. CSS source ceiling is 84,000 bytes summed across all three layers and CSS gzip ceiling 17,000; JS remains 10,000 bytes raw. The new ceiling allows this shared design pass and modest maintenance, not unlimited features. Gzip is a regression signal, not a claim about runtime transfer, startup or CPU. Thresholds are enforced in one shared script and tested at their boundaries; reassess after actual isolated Pages startup, CPU and performance observations. Do not infer production readiness from them.

The present Worker is 404,202 bytes raw, 123,324 gzip; combined CSS source 80,795 bytes, served CSS 79,707 raw / 15,810 gzip; JS 9,765 raw. Worker SHA-256 `cd87bf2ffedee166d271dd90a0a51090b6ee05869509fb69326486f37b09c5c1`. Sources and gzip figures are measured by `node cloudflare/site-v2/budgets.mjs` after a build.

## Design work and verification

The shared signature introduces an editorial red library cover, book-spine cards, a highlighted practice surface, consistent hero rules, coordinated program/assessment surfaces, logical RTL edges and restrained hover motion only when reduced motion is not requested. It uses the existing approved palette and fonts; no new external resources or public features were added. Existing source `site.css` remains large and layered; this is a first extraction of tokens and shared signature, not a completed systematic component migration.

Local offline tests: 132 passed across site, edge and analytics (the separate live-preview test requires a real endpoint and is not included). Isolated browser intercepted the compiled Worker using a synthetic CMS and no production bindings or external images: 51 routes at six widths (306 checks), 51 initial mobile axe scans with zero reported violations, 12 localized book exercises, keyboard and no-JS checks passed. Automated checks do not establish WCAG conformance. The synthetic photos deliberately fail to load and are not evidence of the deployed assets. Local before/after screenshots: `.sandbox/visual-notes-final/` and `.sandbox/visual-signature-final/`; full-page examples `.sandbox/fullpage-signature-final/`. For example, compare `%2Fguides%2F-1440.png` and `%2Ffa%2Fadmissions%2F-390.png` in each directory. Screenshots are test evidence, not a representation of verified production content.
