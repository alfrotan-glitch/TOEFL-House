Production startup/CPU remain unmeasured.

The old source CSS ceiling counted indentation/comments and was 84,000 bytes. It obstructed formatting even when the delivered CSS was identical. The numeric 84,000-byte threshold is now applied to **emitted raw CSS**, while retaining the 17,000-byte gzip, 450,000-byte raw Worker, 140,000-byte gzip Worker and 10,000-byte client-JS ceilings. Source byte count is still reported, but not used as a performance proxy. This change relaxes the earlier source-byte rule and must not be described as unchanged; it does not claim the platform requires these values. Present output: CSS 82,009 raw / 16,284 gzip, source 84,332; Worker 410,078 raw / 120,989 gzip, JS 9,765 raw. Raw CSS has 1,991 bytes of headroom and gzip 716; merely repeating the budget change is not a solution. Complete cascade/asset analysis before further growth.
