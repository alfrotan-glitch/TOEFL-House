## Product change

The four existing original book-guide exercises now each have a visibly framed practice area and an explicitly labelled native textarea in English, Dari and Pashto. The learner can write an answer before opening the existing self-check feedback, and their answer stays in the field while they check it. The field has no enclosing form or submit button, does not require JavaScript, and uses `dir=auto` so typed English and RTL text can use the appropriate direction. The localized label warns that notes are not saved and should be copied before leaving. The website does not intentionally store or transmit notes; browser session restoration, extensions or device software are outside that claim. Learners should avoid sensitive information. This is not publisher content, a placement test or a teacher assessment. Translation, educational quality and manual assistive-technology review are still required.

## Production manifest and HTTP are different evidence

The authorized operator reported that production deployment `ed9c2311-a3b3-4866-b7e4-36a17cb5d298` at source commit `91a6cdaa14df239d9fdb464f4d405df051e20ff7` contains all 25 historical asset paths. This report is path-existence evidence, not proof of byte parity. CI's read-only comparison matched 19 public response bodies against the historical package; public requests for the six historical HTML paths returned 404.

At the reported source commit, the edge Worker sends these HTML paths to `env.ASSETS.fetch` but returns the response only when `asset.ok`; any non-OK response falls through to the Worker 404. Local tests demonstrate this for mocked 301 and 404 asset responses. The three legacy tools routes request the respective index asset internally and return 503 for a non-OK response. A public 404 alone does not identify the real ASSETS status or its cause, prove the file missing, or prove the deployed Worker exactly matches the repository build. Do not infer actual Cloudflare routing or manifest contents from the mock. An operator coordination comment requests per-path current versus historical provider identifiers, SHA-256 of actual bytes, and isolated internal ASSETS/tools verification.

The public response parity gate remains failing; it has not been bypassed or reclassified as success. Current deployment manifest and byte verification, exact read-only preview, real assets/bindings, production security and performance, manual language/accessibility checks, #56 owner approval, and the comprehensive site-wide visual and educational transformation remain open.
